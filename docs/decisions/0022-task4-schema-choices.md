# 0022. Schema and repositories (Roadmap Task 4): choices the docs left open

## Context

The Task 4 plan listed the points that [data-model.md](../data-model.md), [0010](0010-database-postgres-supabase.md) and [0013](0013-drizzle-orm-and-kit.md) leave open. The user approved the suggested answers 1 to 13 on 2026-10-25 (source: the user, relayed by the session that started Task 4). Point 14 (is Supabase ready) was not answered clearly, so Supabase is treated as not ready: nothing was run against it.

## Choice

1. Driver: `pg` 8.23.1 (`node-postgres`).
2. `drizzle-orm` 0.45.4 and `drizzle-kit` 0.31.11, pinned together (the 1.0 release candidates are not used).
3. One `src/db/schema.ts`; camelCase TypeScript fields, snake_case columns.
4. Migrations in `drizzle/` at the repo root, generated by `drizzle-kit generate`.
5. `DATABASE_URL` is required unless `NODE_ENV=test`. Repository tests read `TEST_DATABASE_URL` (in `.env.example`); without it the DB test files fail with a message saying so.
6. Repository tests run on a local `postgres:17` from `docker-compose.yml` (`npm run db:up`), with the same migrations (`src/db/globalSetup.ts` applies them once per run). The compose file maps host port 5433, because 5432 was already taken on the development machine (a decision of the implementation, not of the user): `TEST_DATABASE_URL=postgres://retain:retain@localhost:5433/retain_test`.
7. Tests sit next to the code in `src/` (`src/**/*.test.ts`), repository tests in `src/db/`. They use fresh random ids and never truncate.
8. Enumerations are `text` columns with CHECK constraints (`users.role`, `courses.status`, `enrollments.status`, `reviews.rating`); `card_states.state` is `smallint` with a CHECK between 0 and 3.
9. uuid primary keys with `defaultRandom()`.
10. Repositories: `src/db/cardStates.ts` (`getCardState`, `upsertCardState`), `enrollments.ts` (`presentEnrollment` predicate, `listPresentEnrollments`), `flashcards.ts` (`listFlashcardsByCourse`), `reviews.ts` (`insertReview`, returns false for a repeated delivery). Users and courses repositories come with the tasks that need them.
11. Every repository function takes `db` or a transaction handle (`DbOrTx` in `src/db/client.ts`).
12. Columns are NOT NULL unless data-model.md says null; foreign keys have no cascade (cleanup deletes explicitly, [scheduler.md](../scheduler.md#removed-students-and-cleanup)). `card_states.introduced_at` is NOT NULL (a row exists from the first send). Defaults only where the docs name them (`assessment_pass_threshold` 90, `correct_streak` 0, `reminder_count` 0).
13. Row level security is enabled on every table in the migration (`.enableRLS()`, no policies), closing the Supabase Data API exposure from decision 0010.

## Mapper

`src/db/mappers.ts`: `CardState.last_review` `undefined` becomes NULL and a NULL column leaves `last_review` unset; `learnedAt` is `Date | null` both ways. `last_review` is the only optional field of the ts-fsrs 5.4.2 `Card`.
